# Davi's voice

Derived from `src/content/posts/pt/por-que-escolhi-astro.mdx`. When he publishes more, update this file from what
he actually wrote, not from what sounds good.

## Stance

- First person singular, plain: "escrevi o que o site precisava", "ficou para depois". Not "nós", not "você vai
  aprender".
- He is an engineer explaining a decision to another engineer. He states it, shows the evidence, names the cost.
- Confident without selling. No superlatives about tools ("incrível", "poderoso"). The tool is good because of a
  specific property, and he names it.

## Sentences

- Short. Most sentences under 20 words; none over 35.
- Subject, verb, object. Few subordinate clauses, few commas.
- Concrete nouns: `git push`, CDN, cold start, schema Zod. Avoid abstractions like "experiência", "solução",
  "ecossistema" unless they name something specific.
- Portuguese from Brazil, informal but correct. English technical terms stay in English when that is what people
  say (build, deploy, schema, slug). No forced translations ("implantação" for deploy).

## Structure

- Opens directly in the first `##` with the problem or the requirement. No preamble, no "neste artigo".
- Sections named after their content: "O que eu precisava", "Estático primeiro", "Conteúdo como dado tipado".
  Never "Introdução", "Conclusão", "Considerações finais".
- A short list only when the items are truly parallel (requirements, steps). Reasoning stays in prose.
- Code is evidence: real file, `title="…"`, short. Prose before it says what to look at; prose after it, if any,
  says what it buys.
- Ends on what is left, what was deferred or the trade-off, in a section like "O que ficou para depois". No recap,
  no call to comment, no "espero que tenha gostado". The site already adds a contact CTA after the post.

## Length

The first post has about 300 words. That is fine. Longer only when the topic carries it.
